# v159.2 — Restricted acceptance evidence submissions

Adds separately persisted, metadata-only evidence submissions and append-only review events. These are NOT officer case records. Authorization requires active National Administrator, nationwide scope, administration and intelligence viewing permission. POST `/api/assistant-evaluation/acceptance-submissions` accepts one known track and an opaque safe reference (not a URL or source text), and records submission. POST `/.../{evidence_id}/review` permits another National Administrator to record only EVIDENCE_REVIEWED or REVISION_REQUESTED. The submitting user cannot review their own entry. Re-review requires a new submission, preserving history. GET `/api/assistant-evaluation/acceptance-submissions` returns up to 100 recent entries, statuses and event history.

No actual legal or client sign-off is asserted by these review events; readiness/CSV calculations remain conservative. Reference identifiers must resolve through a separately approved secure evidence repository, and all formal external decisions require authorized client procedures. Existing casework records and approvals are untouched. New migration creates two restricted, RLS-enabled Supabase tables. Automated tests use isolated SQLite fixture records only.
