## Setup
- Blueprint: render-gate1-qa.yaml, separate web service only, linked to existing database via fromDatabase. The YAML contains NO credentials and requires no additional paid service.
- Image: ghcr.io/transformers-enzee/bawaslu-standalone:staging-186.6.
- QA startup is gated by database name, dedicated user, Render host, two explicit QA flags and read-only worker mode. The existing shared BAWASLU staging service cannot pass these database checks.
- Initial startup creates schema and **6 ordinary fictional campaign posts** (baseline + 5 varied categories), **1 watchlist-only** record, 5 fictional assessments, and 2 fictional user accounts.
- QA campaign is DRAFT, ID 1, only synthetic provider GATE1_QA_SYNTHETIC is allowed for corrections. No paid AI or social provider keys are configured. Gate 2 publication remains independent.

## Officer walkthrough (QA sandbox only)
1. Log into the separately named QA service as the fictional admin.
2. Intelligence Inbox > Human Gate 1 > choose BAWASLU Gate 1 QA Pilot.
3. Verify 6 ordinary evidence posts; switch categories to see unassessed, uncertain, excluded and relevant.
4. Open a fictional source. Confirm canonical URL is example.invalid and original evidence is preserved.
5. Record a fictional correction and reviewer reason; check the feedback queue and audit revisions.
6. Run Check insight-draft readiness; confirm independent Gate 2 approval is still mandatory and there is no Command Centre publication.
7. Log in as fictional viewer and confirm all Gate 1 correction/triage writes are denied.

## Safeguards
- No database host with supabase, no operational database, and no SQLite fallback is eligible for QA seeding.
- The run is idempotent: if the exact expected QA fixture already exists, no records are overwritten; unknown existing data causes a hard failure.
- Only a disposable localhost Postgres can bypass the Render host check, and only in explicitly opted-in CI.
- Normal staging deployment retains BAWASLU_GATE1_QA_BOOTSTRAP unset and BAWASLU_STARTUP_READ_ONLY=1; no schema or seed writes occur on the operational database.
- Render free Postgres is **not** long-term persistent; plan a separate paid/eligible project before 2026-12-27 if test revisions must be retained.
